# HarborGrid · 港口集装箱堆场作业协同与闸口调度系统

React + Vite + TypeScript 前端，Node.js + Express + TypeScript 服务端。面向中型集装箱码头，把船期、箱务、堆场区块、闸口预约、设备作业和异常闭环放在同一套作业控制台中。

## 启动

```bash
npm install
npm run dev
```

前端默认 Vite 端口 5178，API 默认 `http://localhost:4107`。

## 业务能力

- 船舶航次、泊位窗口、计划/已完成翻箱和延误风险
- 箱号、尺寸、冷藏温度、危险品级别、海关状态、进出口/中转流向
- 堆场区块容量、堆存热度、冷藏插座、危险品隔离和设备可达性
- 闸口预约时隙、车道、OCR/称重/封志校验状态与同车冲突检测
- 闸口离线作业队列：断网期间车检步骤本机持久化、按设备序号批量同步、幂等键去重、跨闸口重复签到互斥、时钟偏差与预约取消校验、乱序补齐自动对账、逐步返回接受/冲突/人工复核
- 岸桥、场桥、集卡、正面吊设备池和约束感知任务队列
- 自动堆位推荐、冷藏/危险品约束、海关查验阻塞、任务指派审计
- React 控制台支持船期驾驶舱、闸口操作、闸口离线作业、堆场热区与设备任务操作

当前使用内存种子数据，领域服务通过 REST API 暴露，后续可接入 TOS、OCR、称重、RTG 遥测、预约配额和优化求解器。

## 闸口离线作业队列与同步

网络不稳定时，司机完成 OCR、称重、封志检查后结果可能暂时无法到达服务端，值班员不应让车辆反复操作。

**浏览器端（`client/src/gateQueue.ts`、`GateOffline.tsx`）**

- OCR / 称重 / 封志 / 签到四类受支持步骤入本地队列，写入 `localStorage`；浏览器刷新、工位重启后队列与历史裁决不丢失，发送中崩溃的步骤恢复为待上传
- 每台闸口维护独立单调序号 `seq`，重新联网后按设备分组、按序号批量 POST 到 `/api/gate/sync`；联网与 `online` 事件、15 秒轮询、手动按钮均可触发
- 每个步骤生成幂等键，部分成功后整批重试不会重复执行；`conflict` / `review` 保留在队列里由值班员处理或重采，不做自动轰炸式重试
- 与 `/api/gate/devices` 对时，界面显示本机与服务端时钟差；提供"模拟断网""设备时钟偏移"用于演练
- 预约与箱务参考数据缓存本机，完全离线时仍可选择预约、登记车检

**服务端（`server/src/gateSync.ts`）**

- `accepted` / `conflict` / `review` 三态逐步裁决并解释原因（缺检查、时钟偏差、窗口外、海关未放行、重复签到、读数冲突、预约取消等）
- 幂等键：同一键永远返回同一份（可被后续对账升级的）裁决；同机重采的新读数取代旧的挂起读数，跨闸口读数不一致必须人工判定
- 互斥：同一箱只能在一台闸口签到，第二台闸口（即使对应另一张预约）得到 `already-checked-in-elsewhere`
- 时钟：业务时间只信服务端时钟，设备偏差超 3 分钟的签到转人工；物理读数偏差只记录
- 乱序：先到的签到缺前置检查时挂起为 `exception`（不翻转箱态），迟到的检查结果补齐后批次末自动对账放行
- 同步期间预约被取消/删除：后续步骤全部 `conflict`，不写入任何业务字段
- 每一步都写 `GATE_SYNC_STEP` / `GATE_CHECKIN_RECONCILED` / `GATE_READING_SUPERSEDED` 审计，响应回传预约与箱的最终状态，可解释每个接受/拒绝结论
- 相关接口：`GET /api/gate/devices`（对时+设备表）、`POST /api/gate/sync`（批量同步）、`GET /api/gate/sync-records`（裁决台账）

测试见 `server/src/gateSync.test.ts`（幂等重试、乱序对账、跨闸口互斥、同步中取消、时钟偏差、部分成功重试、海关/窗口拦截）。
